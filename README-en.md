# BMS vs Taranovsky's C

[English](README-en.md) | [Japanese](README.md)

A translation function and a correspondence table from the Bashicu Matrix System (BMS, BM4)
to Taranovsky's ordinal notation C (main system, combined).

- Converter (browser): https://koteitan.github.io/bms-vs-taranovskys-c/
- Correspondence table: [sheet/README-en.md](sheet/README-en.md)

## Goal

Build a **total translation function** that takes a BMS matrix and returns a C term, **directly from the matrix**.

- The translation is computed from the input matrix alone. It does not look up a table.
- The sheet (BM4-Analysis) is **only a sample**: part of the test inputs, and values to compare with.
- The sheet's UNOCF labels and ordinal collapsing functions (OCFs) such as extended Buchholz ψ are **references only**.
  The translation does not pass through them: an intermediate notation is weaker than BMS and C, and runs out first as
  the number of rows grows.
- Correctness is checked on the BMS and C sides only (see "Correctness criterion" below).

## Definitions

### Taranovsky's C (main system)

Terms: `0`, `Ω_n` (n ≥ 1), `C(a,b)`. Compared lexicographically as postfix strings
(`post(C(a,b)) = post(b) post(a) C`) with `C < 0 < Ω_n`. Standard form in the n-th system:

    C(a,b) is standard ⇔ a, b are standard
                       ∧ (b = 0 ∨ b = Ω_n ∨ b = C(c,d) with a ≤ c)
                       ∧ a is n-built from below from < C(a,b)

where n-built from below is a direct port of `IsBuiltFromBelow` in Taranovsky's own
`OrdinalArithmetic.py`. In the combined system `Ω_i` is written `Ω_i`, not `C(Ω_{i+1},0)`.

### Fundamental sequences (expand)

Taranovsky does not define fundamental sequences. We use Hyp cos's definition

    α[k] = max{ β < α | β standard, L(β) ≤ L(α) + k }   (L = number of C's)

with `L` counted in the system n = max{i | Ω_i occurs in α}.
The implementation searches the length-bounded lexicographic predecessor on postfix strings,
pruning with the theorem (from Taranovsky's page) that closing a prefix of a standard term's
postfix string with C's yields a standard term.

### BMS

BM4. `M[n]` follows the yaBMS convention (append n copies of the bad part; `M[0]` drops the last column).

### Correctness criterion

The translation f must satisfy:

- f(M) is a standard C term
- M < M' ⇒ f(M) < f(M')
- f(M) = sup_n f(M[n]) at every limit matrix M

If this holds at every limit, f is an order isomorphism onto an initial segment, hence unique.
The machine checks test it on finitely many M (not a proof): standard form of f(M), agreement of the matrix comparison
`bcmp` with the term comparison `cmp`, f(M[n]) < f(M), and `supseq(f(M[4]), f(M[5]), f(M[6])) = f(M)`
(the sup of an increasing sequence inside C).

## Translation

### 1 row (primitive sequence)

Read as a forest and map into the 0-th system with `C(a,b) = b + ω^a`.

### 2 rows (pair sequence)

Map to Buchholz's notation (0, D_ν, +) by p進大好きbot's map,
then to C by the rules ι at the top of `Translate.lean`,
with Ω̂_1 = Ω_1, Ω̂_{ν+1} = C(Ω_2, Ω̂_ν) as the base of D_ν. For ν ≥ 2, when the last term of the argument
has the same level ν, rule N2 replaces its exponent by ψ̂_{ν-1}(Ω_ν + a). For the last term of ψ_0(α' + ψ_μ(b)) (μ ≥ 2),
follow the rightmost path inside log ψ_μ(b) through terms of level ≥ μ and replace the exponent of the bare Ω_μ reached by
E = ψ̂_{μ-1}(a) (R2n/R2g; if b = 0 the exponent is E itself). If there is no such path and the last term of b has level m ≥ μ+2,
do the replacement inside ι(b) with E = ψ̂_{m-1}(b) (R2x). The same replacement is done inside ι(b) for ψ_0(α' + ψ_1(b)) (R1d).
Sums and chains are built with the second-argument minimization Cn (R2k, CnAll; by the paper's definition the value is unchanged).

### 3 rows (trio sequence): directly from the matrix (not implemented)

Current work. Leads:

- The 1-row `prss` and a volunteer's partial rules (`refs/wiki/alemagno_bms_to_ton.txt`) build C directly from the tree
  structure of the matrix: a tree made of a root column followed by a sequence X with 1 added to every entry is C(f(X), 0),
  a sequence of trees (a sum) joins C chains, and (0,1) is Ω. Extending this to 3 rows is the first candidate.
- Landmarks: (0,0,0)(1,1,1) ↦ C(C(C(0,Ω_2),0),0) (sup of the 2-row diagonal sequence),
  the ψ(I) matrix (0,0,0)(1,1,1)(2,1,1)(3,1,0)(2,0,0) ↦ C(C(C(Ω_2,Ω_2),0),0) (sup search in the reference implementation).
- Values to compare with (references): the sheet-based values `sheet/tc_map.json`, and a volunteer's table of 3-row BMS vs C
  `refs/wiki/dan_3row.txt`.
- Dead end: translating by the recursion f(M) = sup f(M[n]) alone (`tools/discover.py`) was abandoned because the cost exploded.

### 3 rows, reference implementation (via the sheet)

The sheet's UNOCF label is read as an extended Buchholz ψ term and mapped to C by f = ι∘σ.
ι (`ebp2tc.js`) uses Ω̂_{γ+ω^e} = C(Ω_2 + e, Ω̂_γ) for transfinite subscripts, and
σ (`ebp_sigma.js`) sends terms whose ι-image drifts because of collapses inside subscripts, order-preservingly, to terms ι handles
(e.g. ψ_0(Ω_{Ω_2}·2) ↦ ψ_0(Ω_{ψ_2(Ω_{ψ_1(Ω_{Ω_2}·2)})})).
It cannot translate rows missing from the sheet and inherits errors of the sheet's labels. **Use it only to compare values with the
direct translation.**

## Usage

    lean/.lake/build/bin/bms2tc "(0,0)(1,1)"          # BMS → C
    bms2tc tc-expand "C(Ω_1,0)" 3                     # fundamental sequence α[3]
    bms2tc tc-fs "C(C(Ω_2,Ω_1),0)" 0 5                # α[0..5]
    bms2tc tc-std "<tc>"                              # standard-form check
    bms2tc tc-cmp "<tc>" "<tc>"                       # compare
    bms2tc bms-expand "(0,0,0)(1,1,1)[2]"             # BMS expansion
    bms2tc batch  < commands.txt                      # batch

Build: `leanman build -C lean` (or `env --chdir=lean lake build`).

The browser version needs no build: open `index.html`. The input is mirrored to `?bms=`.

## Verification

1 and 2 rows, and the implementation of each notation:

- `tools/gen_tc_tests.py` → `lean/tests/TCTest.lean`: 3000 standard-form and 900 comparison cases against
  Taranovsky's Python; 846 fundamental-sequence cases computed by brute force (terms with ≤ 6 leaves).
- `tools/gen_bms_tests.py` → `lean/tests/BmsTest.lean`: 654 cases against yaBMS `bms`.
- `tools/gen_buchholz_tests.py` → `lean/tests/BuchholzTestInline.lean`: against the reference implementation (naruyoko's JS).
- `tools/gen_translate_tests.py` → `lean/tests/TranslateTest.lean`: 441 cases against the Python rules (`tools/pss_tc.py`).
- `tools/check_js.js`: 705 cases `bms2tc.js` vs the Lean CLI (0 mismatches).
- `tools/pss_tc.py`: machine check of the translation: f(M) standard, order preserved,
  f(M[n]) < f(M) (n ≤ 12) and f(M)[k] ≤ f(M[12]) (k ≤ 6). Results in `sheet/verify_bad.json`.
- `tools/rule_lab.js`: lab for the 2-row rules. At each limit M among the sheet rows and matrices reached by expansions, it compares
  f(M) with `supseq(f(M[4]), f(M[5]), f(M[6]))`. **The checks for the direct 3-row translation are to be built the same way.**

Reference implementation (3 rows via the sheet):

- `tools/ebp_lab.js`: over the extended-Buchholz-side fundamental sequence α[n], f(α) = supseq f(α[4..6]), standard form, and order against the neighbouring sheet row.
- `tools/ebp_std_rule.js`: checks the condition (rule R4) under which ι(t) is a standard C term.
- `tools/aaa_cmp.js`: comparison with a volunteer's (AAA) table of extended Buchholz ψ vs C.
- `tools/inspect.js` → `sampling.md`: error counts by ordinal range (1 and 2 rows from the matrix, 3 rows from the reference implementation).
